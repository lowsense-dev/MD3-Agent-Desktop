# MD3 Agent для Linux — дизайн

Дата: 2026-10-21. Исходник: `~/Projects/MD3-Agent` (Android, Kotlin + Jetpack Compose, ~35k строк).

## Цель

Десктопная версия MD3 Agent для Linux: тот же AI-агент с чатом, провайдерами, моделями, агентами, памятью, сжатием, MCP и тулами, в стиле Material 3 Expressive.

Пользоваться будут разные люди на разных дистрибутивах и окружениях. Поэтому приложение не завязано:
- на дистрибутив;
- на DE или композитор;
- на init-систему.

Используются только общие freedesktop-механизмы. Приложение работает на X11 и Wayland, в GNOME, KDE, XFCE, Cinnamon, Hyprland, Sway и т. п. Каждый механизм, которого может не быть, имеет запасной вариант.

Целевые дистрибутивы, на которых проверяется установка:
- Ubuntu 24.04 и новее, Debian 12 и новее;
- Fedora (актуальная);
- openSUSE Tumbleweed;
- Arch;
- остальные через AppImage.

Готово, когда:
- собирается через `./gradlew` на любом Linux с JDK 21;
- собираются пакеты deb, rpm, AppImage и PKGBUILD для Arch, и каждый ставится и запускается на своих дистрибутивах (проверка в контейнерах);
- каждый тул работает или честно отключён с подсказкой, какой пакет поставить;
- перенесённые юнит-тесты и новые тесты Linux-адаптеров проходят;
- реальный запуск: ответ модели, тулы, `run_python`, `run_command` в обоих режимах и напоминание работают.

## Не входит

- Камера.
- Управление экраном и окнами: `phone_screen`, `phone_action`, `read_screen` и всё про accessibility.
- Shizuku, Termux, root, KernelSU-модуль, LSPosed, AlarmManager, VoiceInteractionService, wake word.
- Трей: на Wayland он работает по-разному в разных DE.
- Flatpak и Snap в первой версии. Их песочница ломает главное: режим «Система» у `run_command`, системный Python и вложенный bwrap. Обойти можно только через `flatpak-spawn --host`, а это отдельная работа.
- Постоянная синхронизация с телефоном. Есть только одноразовый импорт.
- Публикация на GitHub, во Flathub, AUR и прочие репозитории, пока пользователь не попросит.

## Архитектура

- Новый репо `~/Projects/MD3-Agent-Linux`, коммиты только локальные.
- Один Gradle-модуль `app`: Kotlin/JVM, Compose Multiplatform Desktop, JDK 21.
- Код копируется из Android-проекта с той же структурой пакетов (`dev.huecoder.md3agent`). Android-зависимые части заменяются реализациями под Linux.

### Переносится почти без изменений

`llm/`, `llm/wire/`, `llm/models/`, `conversation/`, `tools/` (кроме телефонных), `mcp/`, `prompt/`, `net/` и `data/`. В `data/` используется Room KMP с bundled SQLite-драйвером и DataStore KMP. Из `ui/` и `feature/` переносится всё, кроме камеры, phone use и экранов Android-разрешений. Библиотеки берутся в KMP/JVM-вариантах: lifecycle-viewmodel, navigation-compose (JetBrains), Coil 3, multiplatform-markdown-renderer, material-kolor, Material Symbols, graphics-shapes, dyn4j, jlatexmath, OkHttp, kotlinx.serialization.

### `system/` под Linux

У каждого адаптера есть проверка доступности при запуске и запасной вариант.

| Пакет | Основной путь | Если недоступно |
|---|---|---|
| `shell/` | «Система»: `bash -lc` (или `sh -lc`, если bash нет) от пользователя | — |
| | «Песочница»: `bwrap`, видна только рабочая папка агента, сеть по переключателю. Убивается всё дерево процессов | Если `bwrap` нет или не запускается (например, user namespaces запрещены AppArmor на Ubuntu 24.04+), режим недоступен, в настройках причина и как включить |
| `python/` | `python3` из venv агента (`$XDG_DATA_HOME/md3-agent/venv`, создаётся при первом запуске) в отдельном процессе. Таймаут, kill при отмене. В песочнице через `bwrap`. Агент может ставить пакеты в venv через pip | Если модуля `venv` нет (Debian/Ubuntu без `python3-venv`), используется системный `python3` без установки пакетов, с подсказкой |
| `reminders/` | Планировщик внутри приложения. Пока приложение закрыто, работает systemd user timer (`md3-agent-reminder-<id>.timer`), который запускает `md3-agent --reminder <id>` | Без systemd user (Void, Alpine, Artix, Gentoo/OpenRC, контейнеры): напоминания срабатывают только при запущенном приложении. Пропущенные показываются при следующем запуске с пометкой «пропущено». В настройках предупреждение |
| `notifications/` | `org.freedesktop.Notifications` через D-Bus, с кнопками действий («Открыть чат», «Стоп», «Отложить») | Если сервера уведомлений нет, окно поверх всех внутри приложения |
| `files/` | Пикер и сохранение через xdg-desktop-portal FileChooser | Встроенный диалог Compose |
| `clipboard/` | Буфер AWT: текст, картинки, файлы | На Wayland, если AWT не видит файлы или картинки: `wl-paste`. На X11: `xclip` или `xsel` (`text/uri-list`, `image/*`) |
| `secrets/` | Ключ шифрования настроек из Secret Service через D-Bus (gnome-keyring, KWallet 6, KeePassXC) | Файл `$XDG_CONFIG_HOME/md3-agent/key` с правами `0600`, предупреждение в логе и настройках |
| `instance/` | Один экземпляр: Unix-сокет `$XDG_RUNTIME_DIR/md3-agent.sock` (или `/tmp/md3-agent-$UID.sock`). Повторный запуск с аргументами (`--overlay`, `--chat <id>`, `--reminder <id>`) передаёт команду работающему окну | — |
| `shortcuts/` | Глобальный хоткей оверлея через портал GlobalShortcuts (GNOME 48+, KDE и др.) | В настройках команда `md3-agent --overlay` и короткая инструкция, как повесить её на хоткей в своём DE |
| `appearance/` | Тёмная или светлая тема и акцент из portal `org.freedesktop.appearance` (`color-scheme`, `accent-color`) | Выбор в настройках приложения: Система, Светлая, Тёмная. Если портала нет, «Система» значит светлая. Акцент через material-kolor |

### Данные

Пути берутся по XDG Base Directory, с умолчаниями, если переменных нет:
- `$XDG_DATA_HOME/md3-agent/` (`~/.local/share/md3-agent/`): база, вложения, файлы и venv агента;
- `$XDG_CONFIG_HOME/md3-agent/` (`~/.config/md3-agent/`): настройки (DataStore) и ключ, если нет Secret Service.

## UI

- **Адаптивная раскладка.**
  - Широкое окно: navigation rail, слева список чатов, справа чат (list-detail).
  - Узкое окно: как на телефоне, с нижней навигацией «Чаты / Файлы / Настройки».
- **Тема.** Material 3 Expressive, см. `appearance/`.
- **Ввод.**
  - Enter отправляет, Shift+Enter переносит строку.
  - Ctrl+V вставляет текст, картинки и файлы. Файлы можно перетащить в окно.
  - Скрепка открывает меню «Фото / Файлы» (системный пикер, для «Фото» с фильтром по картинкам).
- **Хоткеи.** Ctrl+N новый чат, Ctrl+K поиск, Ctrl+, настройки, Esc закрывает диалог или останавливает ответ.
- **Оверлей.** Компактное окно поверх всех: быстрый вопрос, кнопка «Развернуть» переносит его в полный чат. Контекста экрана нет.
- **Голос.**
  - Диктовка: запись с микрофона через Java Sound (PulseAudio и PipeWire через ALSA-совместимость), распознавание через Whisper-совместимого провайдера из настроек.
  - Озвучка ответов: TTS-провайдеры как на телефоне.
  - Если микрофона нет, кнопка диктовки скрыта.
- **Масштаб.** Учитывается `GDK_SCALE`, а также масштаб из настроек приложения на случай, если окружение не отдаёт его в JVM.
- **Без изменений:** аватар с физикой, markdown, LaTeX, графики, диаграммы, анимации набора, сжатие и счётчик контекста, статистика.

## Импорт с телефона

- **Android (MD3-Agent), отдельный локальный коммит:** в настройках «Экспорт для ПК». JSON содержит провайдеров с ключами, агентов, MCP-серверы, память, настройки и, по галочке, чаты с вложениями. Ключи и токены шифруются паролем: PBKDF2-HMAC-SHA256 (600 000 итераций) + AES-256-GCM. Файл сохраняется через системный пикер.
- **Linux:** в настройках «Импорт с телефона». Нужен пароль. Импорт добавляет записи и ничего не удаляет. Совпадающие по id записи перезаписываются после подтверждения.
- Формат версионируется (`"format": 1`). Неизвестная версия отклоняется с понятной ошибкой.

## Сборка и пакеты

Разработка: `./gradlew run`.

| Формат | Для кого | Как | JRE |
|---|---|---|---|
| `.deb` | Debian, Ubuntu, Mint, Pop!_OS | `./gradlew packageDeb` (jpackage) | Вшита (jlink, только нужные модули) |
| `.rpm` | Fedora, openSUSE, RHEL-подобные | `./gradlew packageRpm` (jpackage) | Вшита |
| AppImage | Любой дистрибутив с glibc | Из `createDistributable` + `appimagetool` | Вшита |
| PKGBUILD | Arch и производные | Собирает uber-jar, `depends=(java-runtime>=21)` | Системная |

Во всех форматах одинаковые:
- запускатель `md3-agent`;
- `md3-agent.desktop` (с `StartupWMClass`);
- иконка в hicolor;
- MIME для открытия файлов не регистрируется.

Необязательные зависимости объявляются как Recommends/Suggests (deb, rpm) и `optdepends` (Arch): `bubblewrap`, `python3` с venv, `wl-clipboard`, `xclip`, `xdg-desktop-portal`.

Ограничения:
- Окно рисуется через XWayland на Wayland и нативно на X11. Нативного Wayland в обычном OpenJDK нет, это известное ограничение.
- AppImage требует glibc. Alpine/musl поддерживается только сборкой из исходников с системной JRE.

## Ошибки

- Ошибки сети, API, MCP и тулов показываются в чате, как на телефоне.
- Если внешней программы, портала, Secret Service, systemd или сервера уведомлений нет, работает запасной вариант из таблицы `system/`. Без запасного варианта тул отключается с подсказкой. Приложение никогда не падает из-за отсутствия системного компонента.
- Проверка окружения доступна в «Настройки → О приложении → Окружение»: что найдено, что нет, какой пакет поставить.

## Тесты

- Перенесённые юнит-тесты из Android-проекта, без телефонных.
- Новые тесты:
  - аргументы `bwrap` для обоих режимов и сети;
  - текст systemd `.timer` и `.service`, а также поведение без systemd (пропущенные напоминания);
  - разбор `text/uri-list` и данных буфера;
  - пути XDG с переменными и без них;
  - определение дистрибутива по `os-release` и имена пакетов;
  - шифрование и расшифровка файла экспорта, неверный пароль, неизвестная версия;
  - протокол сокета одного экземпляра.
- UI проверяется headless-рендером экранов в PNG (`ImageComposeScene`): чат, список, настройки, оверлей, узкая и широкая раскладки, светлая и тёмная темы. Окна на рабочем столе пользователя не открываются.
- Установка проверяется в контейнерах (podman или docker, что есть): `.deb` на Ubuntu 24.04 и Debian 12, `.rpm` на Fedora и openSUSE, PKGBUILD на Arch, AppImage на Ubuntu. В каждом контейнере пакет ставится, а `md3-agent --version` и `md3-agent --check-environment` (печатает найденные компоненты и выходит, без окна) отрабатывают.
- В конце один реальный запуск с запросом к модели: проверка тулов, `run_python`, `run_command` (оба режима) и напоминания.
